# 出题规范：第三套盲写评测题

你要为一个"用中文问数据库"的 Text2SQL 系统写评测题。系统收到一个中文问题，自己找出相关的表和字段、
写 SQL、执行、返回结果；评测时，把系统返回的结果和你写的参考 SQL 的执行结果比对。

## 能用的材料（只用这些）

- `ecommerce.md`、`chinook.md`：两个库的建表语句和数据字典（表描述、字段描述）
- `ecommerce.db`、`chinook.db`：两个 SQLite 库本身，可以随意查询，用来探数据、验证参考 SQL
- `evalcase.py`：题目的数据结构

## 不要做的事

- 不读本目录以外的任何项目文件：包括 README、docs/、eval/ 下的已有题目、git 历史
- 不运行被测系统，也不读它的代码
- 如果你的会话环境里自动带了项目信息（例如 git 状态、提交标题），不要据此出题，并在最后的报告里如实说明看到了什么
- 有任何例外（比如不小心看到了什么），如实报告

## 题量

- ecommerce：30 题，题号 `H3E01`–`H3E30`，其中陷阱题 3 道
- chinook：20 题，题号 `H3C01`–`H3C20`，其中陷阱题 3 道
- 难度有易有难，覆盖每个库的全部 11 张表

## 让题目可判分

1. **口径写清**：指标怎么算、算哪些状态、日期区间含不含首尾、按什么去重，都要在问题里说清楚。
   只看数据字典的人，应该能据此写出唯一正确的结果
2. **输出列写清**：说清楚返回哪些列，例如"返回店铺名称和金额"、"返回一个数"
3. **TopN 无并列**：问前 N 名时，第 N 名和第 N+1 名不能并列
4. **答案不退化**：结果不能是 0 行，也不能是单个 0 或 NULL
5. **枚举取值用原文**：问题里出现的枚举取值，必须是库里的原文；系统应当按这个取值筛选
6. **小数位写明**：需要保留小数的，在问题里写明保留几位，参考 SQL 里用 ROUND
7. **行序**：结果比对默认不看行序。只有问题明确要求排序、且排序没有歧义时，才设 `ordered=True`

## 字段怎么填（见 `evalcase.py`）

- `id`、`query`（中文问题）、`reference_sql`（在对应的库上能直接执行）
- `must_hit_columns`：答对这道题必须用到的字段，写成 `"表名.字段名"`。同一个需求有几条同样正确的
  路径时，写成候选列表 `["表A.字段", "表B.字段"]`，命中任意一个即可——前提是你验证过每条路径的
  结果完全一致
- `tags`：难度（`难度:简单` / `难度:中等` / `难度:难`）加考点
- `note`：一两句口径说明，写清这道题考什么、为什么答案唯一
- **陷阱题**：库里根本没有数据能回答的问题。`reference_sql="SELECT 1 WHERE 0"`、`must_hit_columns=[]`、
  `expect_unanswerable=True`，`tags` 里带 `陷阱题`。系统的正确行为是说明缺失，而不是编一个答案。
  陷阱题避开数据字典里已经写明"答不了"的主题

## 交付

1. 把 50 道题写进本目录的 `cases_holdout3.py`：两个列表 `HOLDOUT3_ECOMMERCE_CASES`、
   `HOLDOUT3_CHINOOK_CASES`，用 `from evalcase import EvalCase` 导入数据结构
2. 自己做一遍校验：每条参考 SQL 在对应的库上跑通、结果不退化、TopN 不并列、必中字段真实存在。
   有候选路径的题，把你验证用的其他路径的 SQL 写进本目录的 `alt_sql.json`（题号 → SQL 列表）
3. 最不放心的题，在它的 `note` 开头加"【存疑】"并写明原因
4. **最后的回复里不要写任何题目内容**——问题、SQL、字段、口径都不要写。只报告：文件路径、
   各库题数和陷阱题数、存疑题的题号、你遵守上面限制的情况，以及任何例外（包括会话环境里自动带的信息）
